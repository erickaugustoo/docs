A Integra tem um servidor MCP (Model Context Protocol). Por ele, o Claude, o Claude Code e o ChatGPT consultam a sua operação, cuidam do CRM e das Automações e fazem ações na sua conta com o seu login, só na organização que você escolher ao conectar.

Para usar no Claude ou no ChatGPT, siga [Claude e ChatGPT](/assistentes-de-ia). Esta página mostra como conectar o Claude Code e reúne os detalhes técnicos do servidor.

## Dados do servidor

| Item | Valor |
| --- | --- |
| Endereço | `https://mcp.useintegra.com.br/mcp` (sem barra no final) |
| Transporte | Streamable HTTP |
| Login | OAuth 2.1 com PKCE, na mesma conta do painel |
| Aplicativos aceitos | Claude, Claude Code, ChatGPT e outros clientes MCP que se identificam por um documento de metadados em `https` |
| Token de acesso | Vale 1 hora, e o aplicativo renova sozinho |
| Conexão sem uso | Depois de 30 dias parada, é preciso entrar de novo |
| Validade da conexão | 90 dias desde a conexão, mesmo em uso. Depois, é preciso conectar de novo |

<Note>
  Qualquer aplicativo pode pedir a conexão, mas quem decide é você: a tela de permissão mostra o nome e o domínio do aplicativo. Confira os dois antes de clicar em **Permitir**.
</Note>

## Conectar no Claude Code

<Steps>
  <Step title="Adicione o servidor">
    No terminal, rode:

    ```bash
    claude mcp add --transport http integra https://mcp.useintegra.com.br/mcp
    ```

    Assim a Integra fica disponível só para você, no projeto atual. Para ter a Integra em todos os seus projetos, use `--scope user`:

    ```bash
    claude mcp add --transport http --scope user integra https://mcp.useintegra.com.br/mcp
    ```
  </Step>
  <Step title="Entre na Integra">
    No Claude Code, rode `/mcp`, escolha **integra** e depois **Authenticate**. O navegador abre o login da Integra. Use a mesma conta do painel.
  </Step>
  <Step title="Escolha a organização">
    Escolha as permissões que quer liberar e a organização, e clique em **Permitir**. De volta ao Claude Code, as ferramentas aparecem com o prefixo `mcp__integra__`, como `mcp__integra__resumo_da_operacao`.
  </Step>
</Steps>

### Para a equipe toda

Com `--scope project`, o Claude Code grava o servidor no `.mcp.json` do repositório. Quem abrir o projeto vê a Integra na lista e entra com a própria conta:

```json .mcp.json
{
  "mcpServers": {
    "integra": {
      "type": "http",
      "url": "https://mcp.useintegra.com.br/mcp"
    }
  }
}
```

<Tip>
  O Claude Code pede confirmação antes de cada ferramenta. Para pular a confirmação só nas consultas, coloque as ferramentas de consulta em `permissions.allow` no `.claude/settings.json`, uma por uma (por exemplo, `mcp__integra__buscar_historico`). As que criam, publicam, enviam ou apagam continuam pedindo confirmação.
</Tip>

<Note>
  No Claude e no Claude Code, o servidor não dispara ligações: `criar_campanha` aceita só WhatsApp, e `retentar_falhas` e `ligar_para_testar_agente` não aparecem. Pelo mesmo motivo, `configurar_lembrete_de_reuniao` ajusta só o lembrete pelo WhatsApp, `publicar_automacao` e `retomar_automacao` recusam a automação que tem bloco Ligar, e `tentar_de_novo` não repete um passo de ligação. As campanhas de voz, a repetição de falhas, o teste por ligação, o lembrete por ligação e as automações que ligam ficam no ChatGPT e no painel.
</Note>

## Permissões

Cada grupo de ferramentas depende de um escopo OAuth. Na tela de conexão, você escolhe quais liberar antes de clicar em **Permitir**: a consulta (`integra:read`) vem sempre, e as outras vêm marcadas para você desmarcar o que não quiser. O aplicativo só recebe as ferramentas dos escopos liberados.

| Escopo | O que libera | Ferramentas |
| --- | --- | --- |
| `integra:read` | Consultar resultados, ligações, conversas, agentes, campanhas, reuniões, métricas e configurações. Sempre incluído | 27 |
| `integra:campaigns` | Criar e cancelar campanhas e repetir as falhas | 3 (2 no Claude) |
| `integra:agents` | Criar, configurar, publicar, ativar e desativar agentes, vincular números, adicionar vozes da biblioteca, definir o horário da agenda e o lembrete de reunião, e ligar para testar | 10 (9 no Claude) |
| `integra:inbox` | Assumir, devolver e responder conversas do Inbox | 2 |
| `integra:crm` | Ver, alterar e apagar contatos, empresas, negócios, tarefas e anotações, configurar funis, colunas personalizadas e o CRM, e montar, publicar e acompanhar as Automações | 46 |

O CRM e as Automações ficam inteiros em `integra:crm`, inclusive a consulta: sem esse escopo, o aplicativo não vê contatos, negócios nem automações.

A tela oferece os escopos que o aplicativo pediu; se ele não pedir nenhum, oferece os cinco. Para saber o que uma conexão pode fazer e o que falta liberar, use `minha_conta`. Para liberar o que falta, desconecte e conecte de novo, marcando a permissão.

O seu papel na organização continua valendo: o que você não pode fazer no painel, o servidor também não faz.

## Ferramentas

São 88 ferramentas: 27 de consulta, 3 de campanhas, 10 de agentes, 2 do Inbox e 46 do CRM e das Automações. No Claude e no Claude Code são 86, porque `retentar_falhas` e `ligar_para_testar_agente` não aparecem (veja a nota acima). No ChatGPT aparecem as 88.

As respostas vêm em JSON, e os horários vêm em UTC (ISO 8601, terminados em `Z`). Na maioria das ferramentas, a resposta que dá certo traz no campo `painel` o link da tela correspondente no painel. Nenhuma resposta mostra créditos, custo nem saldo: o consumo fica no painel. O valor de um negócio do CRM é dado seu e aparece normalmente.

#### Colunas personalizadas

As colunas personalizadas guardam o que é só do seu negócio, como o convênio de um paciente ou a data do retorno. Cada coluna pertence a contatos, empresas ou negócios e tem um tipo: texto, número, data, seleção ou sim/não. Nas ferramentas, elas aparecem como `campos`.

| Ferramenta | O que faz |
| --- | --- |
| `listar_campos_do_crm` | As colunas ativas de contatos, empresas e negócios: chave, rótulo, tipo, opções da seleção e se o agente preenche |
| `salvar_campo_do_crm` | Cria ou edita uma coluna. Para criar, informe onde ela fica (contato, empresa ou negócio), o rótulo e o tipo. A chave sai do rótulo. Numa coluna que já existe, mudam o rótulo, as opções e se o agente preenche; a chave e o tipo não mudam. Contatos, empresas e negócios aceitam até 50 colunas ativas cada. Só administrador |
| `arquivar_campo_do_crm` | Arquiva uma coluna: ela some da lista e deixa de valer nos registros novos. Os valores já gravados ficam. Pelo servidor não dá para desarquivar. Só administrador |

Para preencher as colunas, `salvar_contato` e `criar_negocio` aceitam `campos`, um objeto `{ chave: valor }`. Este é um exemplo de entrada do `salvar_contato`:

```json
{
  "telefone": "+5511999998888",
  "campos": {
    "convenio": "Unimed",
    "retorno": "2026-12-01",
    "primeira_consulta": true
  }
}
```

- A chave é a da coluna, que o `listar_campos_do_crm` mostra.
- O valor segue o tipo da coluna: texto (até 500 caracteres), número, data no formato `AAAA-MM-DD`, uma das opções da seleção, `true` ou `false`.
- `null` tira o valor de uma coluna. O que não vier fica como está.
- Chave que não existe ou valor de outro tipo é recusado.

Na leitura, `buscar_contatos` e `ver_contato` devolvem `campos` em cada contato, como uma lista de `chave` e `valor`. Os negócios também trazem `campos` nas respostas. `editar_negocio` e `salvar_empresa` não recebem `campos`.

Num assistente, basta pedir: "Crie a coluna Convênio nos contatos, com as opções Unimed, Amil e Particular, e marque Unimed na Ana."

| `configurar_crm` | Liga ou desliga a criação automática de contatos pelos agentes e a regra de o vendedor ver só os próprios negócios. Só administrador |
| `conectar_crm_integra` | Cria no projeto as 5 funções que o agente usa na conversa para ler e gravar o CRM: buscar contato, salvar contato, mover etapa, anotar e criar tarefa. Depois, inclua as funções no agente com `editar_configuracao_do_agente` e publique. Só administrador |

#### Apagar

| Ferramenta | O que faz |
| --- | --- |
| `apagar_negocio` | Apaga um negócio de vez, com as notas que eram só dele. As tarefas, o contato e a empresa ficam |
| `apagar_contato` | Apaga um contato de vez, com a linha do tempo, as tarefas e as execuções de automação dele. Os negócios ficam, sem o contato. Só administrador |

<Warning>
  Apagar não tem volta. As ferramentas de apagar pedem ao assistente que mostre o que vai sair e espere a sua confirmação. Funil e coluna o servidor só arquiva, e os dados ficam.
</Warning>

### Automações (`integra:crm`)

São 13 ferramentas. Uma automação é um fluxo que roda sozinho entre um atendimento e outro: um gatilho (um evento ou uma agenda) e os blocos que vêm depois, como ligar, enviar template de WhatsApp, esperar, mover de etapa e criar tarefa. O assistente monta a automação num arquivo em YAML ou JSON, com os nomes do que a sua organização tem.

| Ferramenta | O que faz |
| --- | --- |
| `catalogo_de_automacoes` | O ponto de partida para montar uma automação: os gatilhos, os blocos, as marcações, os nomes do que a organização tem (funis, etapas, agentes, números, templates e ferramentas) e o formato do arquivo, com exemplos |
| `listar_automacoes` | As automações, com o status (rascunho, ligada ou pausada), o gatilho, a versão publicada e as execuções dos últimos 7 dias |
| `ver_automacao` | Uma automação com o status, o gatilho, os problemas do rascunho, o resumo dos passos e o arquivo do rascunho |
| `criar_automacao` | Cria uma automação como rascunho, a partir do arquivo. Ela não roda até ser publicada. Se um nome do arquivo não casar com o que a organização tem, nada é criado e a resposta diz o que faltou. Só administrador |
| `editar_automacao` | Troca o rascunho inteiro pelo arquivo enviado. A versão que está rodando só muda quando a automação é publicada de novo. Só administrador |
| `simular_automacao` | Anda pelo rascunho e mostra o caminho que um contato faria em cada desfecho. Não liga, não envia e não grava nada |
| `publicar_automacao` | Valida o rascunho e publica: a automação passa a rodar para contatos reais. Republicar interrompe as execuções em andamento da versão anterior. Conta no limite de automações ligadas do plano. Só administrador |
| `pausar_automacao` | Pausa uma automação ligada e congela as execuções em andamento. Só administrador |
| `retomar_automacao` | Volta a ligar uma automação pausada, e as execuções seguem de onde pararam. Só administrador |
| `despublicar_automacao` | Tira a automação do ar e volta para rascunho. As execuções em andamento param. Só administrador |
| `listar_execucoes_da_automacao` | Onde está cada contato nas automações, com filtro por automação e por status. Com o status de erro, é a fila de erros, com o passo em que parou e o motivo |
| `ver_execucao_da_automacao` | O caminho que uma execução fez, passo a passo, com o status e o motivo de cada um |
| `tentar_de_novo` | Volta uma execução que terminou em erro para o passo em que parou. Corrija a causa antes. Só administrador |

Fora do Claude e do Claude Code, publicar ou retomar uma automação que tem bloco Ligar, ou tentar de novo um passo de ligação, exige também o escopo `integra:campaigns`.

## Como as ações se comportam

As edições de agente vão para o rascunho e só valem depois de `publicar_agente`. Passe a `versao` que o `ver_agente` mostra: se alguém mudou o rascunho no painel nesse meio tempo, a ferramenta não grava e pede para ler o agente de novo.

Pedidos repetidos não executam duas vezes. A mesma `criar_campanha` ou `retentar_falhas` no mesmo dia devolve o que já foi feito. A mesma `criar_agente`, `ligar_para_testar_agente` ou `responder_conversa` em até 2 minutos não acontece de novo.

No CRM, `salvar_contato` com um telefone que já está cadastrado altera esse contato em vez de criar outro, e `salvar_empresa` com o nome de uma empresa que já existe devolve essa empresa. Nas ferramentas de alterar, só muda o que você informar. As listas de etiquetas e de etapas substituem as atuais.

As automações nascem e são editadas como rascunho. Só `publicar_automacao` e `retomar_automacao` fazem a automação rodar para contatos reais, e a versão no ar só muda quando você publica de novo. A exceção é o horário de atendimento: quando o arquivo enviado ao `editar_automacao` traz o horário, ele vale na hora. Sem horário no arquivo, a automação nasce com segunda a sexta, das 09:00 às 18:00, no horário de São Paulo, sem feriados nacionais. O servidor não apaga automação nem execução.

As ferramentas marcadas com "Só administrador" seguem o seu papel na organização: sem ele, respondem que o papel não permite.

Respostas muito grandes voltam cortadas, com um aviso. Nas listas, o campo `itensOmitidos` diz quantos itens ficaram de fora. Peça menos itens ou use os filtros.

Os erros voltam em português, prontos para mostrar a quem está usando: falta de permissão do papel, item que não existe na organização, limite do plano ou muitas chamadas seguidas.

### Limites por conexão

| Ferramenta | Limite |
| --- | --- |
| Todas, somadas | 120 chamadas por minuto |
| `responder_conversa` | 20 por minuto e 200 por hora |
| `assumir_ou_devolver_conversa` | 30 por minuto |
| `criar_campanha`, `retentar_falhas` e `ligar_para_testar_agente` | 5 por hora, cada uma |
| `criar_automacao` | 20 por hora |
| `editar_automacao` e `tentar_de_novo` | 30 por hora, cada uma |
| `publicar_automacao` e `retomar_automacao` | 10 por hora, cada uma |
| As cinco de apagar do CRM, somadas | 10 por minuto e 30 por hora |

Passando do limite, a ferramenta não faz nada e responde quanto tempo falta para tentar de novo.

## Desconectar e trocar de organização

No painel, abra **Ajustes** > **Aplicativos conectados** e clique em **Desconectar**. O aplicativo perde o acesso na hora. A lista mostra cada aplicativo que você conectou, as permissões dadas, quando conectou e o último uso.

Administradores e proprietários veem, na mesma tela, as **Conexões da organização**: os aplicativos que cada membro conectou. Lá, **Revogar** corta o acesso da conexão de qualquer membro na hora. A conexão de um proprietário só outro proprietário revoga.

A conexão também cai sozinha quando a pessoa sai da organização, quando troca a senha e depois de 90 dias.

Cada conexão vale para uma organização. Para trabalhar com outra, desconecte e conecte de novo escolhendo a outra organização. No Claude Code, rode `/mcp`, escolha **integra** e entre de novo.

Se uma ferramenta responder "Esta conexão perdeu o acesso à organização", você saiu da organização ou o seu acesso mudou. Conecte de novo.

## Para quem desenvolve um cliente MCP

O servidor segue a especificação de autorização do MCP:

- recurso protegido: `https://mcp.useintegra.com.br/.well-known/oauth-protected-resource/mcp`
- servidor de autorização: `https://mcp.useintegra.com.br/.well-known/oauth-authorization-server`
- o cliente se identifica por um documento de metadados (Client ID Metadata Document); não há registro dinâmico
- o `client_id` é a URL `https` desse documento, que precisa trazer `client_id`, `client_name` e `redirect_uris`
- o `redirect_uri` tem de ser `https`, ou `http` em loopback (`localhost`, `127.0.0.1` ou `[::1]`)
- PKCE com `S256` é obrigatório, e o parâmetro `resource`, quando enviado, tem de ser `https://mcp.useintegra.com.br/mcp`
- os escopos são os cinco da tabela de Permissões; sem `scope` no pedido, a tela oferece todos
- sem token válido, o `/mcp` responde `401` com o cabeçalho `WWW-Authenticate` apontando para os metadados
- o `/mcp` aceita uma mensagem JSON-RPC por requisição, sem lote
