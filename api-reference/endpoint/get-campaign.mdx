## Campos por canal

O campo `channel` diz se a campanha é de voz ou de WhatsApp, e alguns campos só fazem sentido em um dos dois.

| Campo | `voice` | `whatsapp` |
|-------|---------|------------|
| `agent` | O agente que liga | `null` |
| `phone_number` | O número de origem | `null` |
| `config` | Parâmetros de discagem | `null` |
| `template_name` | `null` | Nome do template aprovado na Meta |
| `started_at` | Quando a campanha começou | `null` |

<Note>
  `started_at` vem `null` no canal `whatsapp` de propósito. Internamente aquele carimbo é o batimento do processo de disparo, recarimbado a cada destinatário, e não o horário em que a campanha começou. Publicá-lo mentiria. Use `created_at` e `scheduled_at`.
</Note>

## Status dos destinatários

Cada item de `recipients` tem um `status` próprio. O canal de WhatsApp usa a escala de entrega da Meta:

| Status | Significado |
|--------|-------------|
| `PENDING` | Ainda não disparado |
| `SENT` | Template entregue à Meta |
| `DELIVERED` | Chegou ao aparelho |
| `READ` | O contato abriu a mensagem |
| `REPLIED` | O contato respondeu |
| `FAILED` | A Meta recusou o envio. O motivo está em `error_message` |
| `CANCELLED` | A campanha foi cancelada antes de disparar este contato |

Os status nunca regridem: um recibo de entrega atrasado não rebaixa quem já respondeu.

<Tip>
  `error_message` traz o erro **cru da Meta**, com código e tudo (por exemplo `(#132000) Number of parameters does not match the expected number of params`). É o único lugar da API que diz por que um envio específico falhou — a lista de campanhas só sabe contar falhas.
</Tip>
